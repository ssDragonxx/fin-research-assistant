# 金融研究智能体 · 技术文档

> 版本 0.1.0 ｜ 2026-10-22 ｜ A 股方向
> 本文面向技术评审，说明系统做了什么、为什么这样设计、哪些地方踩过坑。

---

## 1. 项目定位

一个运行在 Hermes Agent 上的 A 股研究助手，提供两项能力：

- **每日盘后简报**：定时生成行情解读、板块冷热、重点资讯、次日关注、昨日判断回顾
- **个股研究**：输入公司名或代码，输出带数据出处的财务、估值、同业对比与风险提示

**不做**：涨跌预测、买卖建议、目标价。这不是能力限制，是产品定位——不可验证的结论无法评测，也无法对用户负责。

## 2. 架构

### 2.1 三层职责划分

```
┌─────────────────────────────────────────────┐
│  Hermes Agent（LLM）                         │  判断 · 叙述 · 取舍
│  加载 SKILL.md，决定调用哪个命令、怎么组织结论   │
└───────────────────┬─────────────────────────┘
                    │  bash: fin market quote
┌───────────────────▼─────────────────────────┐
│  SKILL.md（270 行）                          │  流程 · 输出模板 · 硬规则
│  触发条件、步骤、完成标准、禁止事项             │
└───────────────────┬─────────────────────────┘
                    │  调用
┌───────────────────▼─────────────────────────┐
│  fin CLI（2,448 行 Python）                  │  取数 · 计算 · 校验
│  只输出 JSON，不含任何自然语言                 │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  数据层：东财（20 个接口）+ 腾讯（行情）        │
│  SQLite 缓存 · 分级降级 · 离线快照             │
└─────────────────────────────────────────────┘
```

**核心原则：数字归 CLI，判断归 Skill。**

LLM 不取数、不做算术、不凭记忆补全。它只能引用 CLI 本次输出的字段。
这条边界是整个系统可靠性的基础——金融场景里，模型编一个数字的代价远高于它写出漂亮的分析。

### 2.2 为什么是 CLI + Skill，而不是纯 Prompt

| 方案 | 数字准确性 | 可测试性 | 维护成本 |
|---|---|---|---|
| 全靠模型联网搜索 | 低，无法溯源 | 无法做快照测试 | 低 |
| 全部写进 Prompt | 低，模型自由发挥 | 无法测 | 中 |
| **CLI + Skill（本方案）** | 高，字段级可追溯 | 命令级快照 + 数字保真度检查 | 中，但数据源变更只改 CLI |

代价是需要维护一个数据适配层。收益是：**任何一个数字都能在 JSON 里找到出处**，
这也是后续做保真度评估的前提。

## 3. 数据层设计

### 3.1 多源与降级

开发当天（2026-10-22）遇到东方财富 `push2.eastmoney.com` 对本机 IP 的 WAF 封禁：
TLS 握手被服务端主动断开，所有镜像域名（`82.push2`、`33.push2` 等）同样被封，
而 `datacenter`、`push2ex`、`np-listapi` 等其它子域不受影响。

这个现实直接改变了选型：

| 用途 | 主源 | 备源 | 降级表现 |
|---|---|---|---|
| 指数/个股行情、PE/PB/市值 | 腾讯 `qt.gtimg.cn` | 东财 `push2/stock/get` | 自动切换，warnings 说明 |
| 涨跌家数 | 东财 `push2/ulist.np` | 无 | 返回 `unavailable: true`，并用涨跌停统计替代 |
| 行业板块 | 东财 `push2/clist` | 数据中心 `RPT_INDUSTRY_FUNDFLOW` | 降级后无涨跌家数，字段说明 |
| 行业归属与成分股 | 数据中心 `RPT_F10_CORETHEME_BOARDTYPE` / `RPT_BOARD_CONSTITUENT` | 无 | 不依赖 push2，稳定路径 |
| 财务指标 | `datacenter.eastmoney.com` | 无 | 缓存兜底 |
| 资讯/公告/研报 | `np-listapi` / `np-anotice` / `reportapi` | 无 | 各自独立降级 |

**设计取舍**：不追求"所有指标都有备份"。涨跌家数没有可靠的备源，
就明确返回缺失并让下游改用替代指标，而不是用 0 或估算值填充。
**缺数据必须是缺失，不能是零**——这是数据产品的基本纪律。

### 3.2 缓存

SQLite 单文件（`~/.fin-data/fin.db`），key 由 endpoint + 参数哈希生成。

| 数据类型 | TTL | 理由 |
|---|---|---|
| 行情 | 120s | 盘中够用，收盘后当日不变 |
| 财务 | 12h | 一季度才更新一次 |
| 板块 | 10min | 盘中变化慢于个股 |
| 资讯 | 10min | 兼顾时效与限流 |
| 符号表 | 24h | 全量列表需翻 56 页 |

**四层降级**：
1. TTL 内命中 → `cache: "hit"`
2. 上游失败 → 重试 1 次
3. 仍失败 → 读过期缓存，`cache: "stale"`，warnings 写入数据时间
4. 无缓存时 → `--offline` 模式读本地快照，用于演示保底

### 3.3 统一 JSON 契约

所有命令返回同一信封：

```json
{
  "ok": true,
  "cmd": "stock.quote",
  "as_of": "2026-10-22T17:05:56+08:00",
  "data": { "300750": { "price": 220.41, "pe_ttm": 11.63 } },
  "sources": [{ "name": "腾讯", "endpoint": "qt.gtimg.cn" }],
  "warnings": ["PE 存在多个口径：动态 11.85 / TTM 11.63，报告统一使用 PE-TTM"],
  "cache": "hit"
}
```

`warnings` 是刻意设计的出口：数据口径冲突、字段缺失、降级原因都必须显式暴露给 LLM，
而不是让它自由发挥。**把不确定性交给模型判断，比让它假装完整更安全。**

## 4. Skill 设计

两份技能共 270 行，每份包含：触发条件 → 执行步骤 → 输出模板 → 硬规则 → 常见错误。

以 `fin-market` 为例，硬规则是：

```markdown
1. 每个数字必须出现在本次 CLI 输出的 JSON 中，不得跨日期拼接。
2. 每段结论末尾标注来源键，如 [market.indexes]、[news]。
3. 数据缺失写"暂无数据"，不得推断、不得用历史数据代替。
4. 不预测涨跌、不给买卖建议。
5. warnings 里的每一条都要在"数据说明"中出现。
```

"常见错误"一节是迭代中补的，记录模型实际犯过的错，例如：

- 把创业板指跌 4% 说成"全市场下跌"（创业板是深市子集）
- 把四个指数的涨跌家数相加（只有沪指 + 深成指可以相加）
- 涨跌家数缺失时写成"0 家"（应读 `breadth.unavailable` 并改用 sentiment）

**输出模板里保留 `[来源键]` 不是装饰**：保真度检查脚本靠它做段落级归因。

### 4.1 `${HERMES_SKILL_DIR}` 占位符

技能内引用 CLI 安装路径时使用 Hermes 提供的模板变量：

```bash
pip install -e "${HERMES_SKILL_DIR}/../.." --quiet
```

加载时会被替换为技能目录的绝对路径（实测验证）。这样 profile 无论装在哪里、
叫什么名字，命令都能正确解析，不需要硬编码路径。

## 5. 风险规则引擎

**规则是确定性的，LLM 只能解释和排序，不能增删命中项。**

| 规则 | 数据来源 | 触发条件 | 分级 |
|---|---|---|---|
| 股价异动 | 日 K 线 | 近 20 日单日跌幅 ≤ -7% | 高（≤-9%）/ 中 |
| 成交量异动 | 日 K 线 | 量比 ≥ 2.5 | 中 |
| 区间回撤 | 日 K 线 | 近 20 日回撤 ≤ -15% | 中 |
| 高负债率 | 财务 | 资产负债率 > 70% | 高（>85%）/ 中 |
| 毛利率下滑 | 财务 | 环比下降 ≥ 5 个百分点 | 中 |
| 亏损 | 财务 | 归母净利润 < 0 | 高 |
| 估值异常 | 行情 | PE-TTM < 0 | 中 |
| 估值溢价 | 同业 | PE 高于行业中位数 150% 以上（≥2.5 倍） | 中 |
| 重大公告 | 公告标题 | 命中关键词库（立案/退市/预亏/减持/质押/诉讼…） | 高 / 中 |
| 解禁压力 | 解禁表 | 未来 90 天内有解禁 | 中 |

每条输出 `{rule, level, evidence, source}`，`evidence` 保留原始数值，方便复核。

实测（宁德时代 2026-10-22）命中 4 条，包括「2026-10-21 单日下跌 -12.03%」——
这条是当天真实发生的行情，不是构造数据。

**为什么不用 LLM 直接判断风险**：漏报和误报都不可复现。
规则引擎可以先给出确定的基线，LLM 负责解释「这条意味着什么」，职责清晰、可回归测试。

## 6. 工程问题与解决

开发过程中遇到并修复的问题，按"最能体现排查能力"排序。

### 6.1 接口声明 UTF-8 实际返回 GBK

**现象**：财务接口返回 200，`json.loads` 解析成功，但 `result.data` 是空数组。

**排查**：直接请求打印原始字节，发现中文全是乱码；但 `decode('utf-8')` **不报错**——
GBK 的双字节序列恰好构成了合法的 UTF-8 字符，只是语义错误。

**根因**：`datacenter.eastmoney.com` 响应头写 `Content-Type: text/plain;charset=UTF-8`，
实际返回 GBK。声明不可信。

**解法**：不能依赖 `UnicodeDecodeError`。改为乱码特征评分：

```python
def _mojibake_score(text):
    score = 0
    for ch in text:
        cp = ord(ch)
        if cp == 0xFFFD: score += 2          # 替换字符
        elif 0x80 <= cp <= 0x24F: score += 1 # 拉丁扩展（GBK 误读的典型产物）
        elif 0x370 <= cp <= 0x52F: score += 1 # 希腊/西里尔
        elif 0x2E80 <= cp <= 0x9FFF: score -= 1 # 正常中日韩字符
    return score
```

UTF-8 与 GB18030 各解一次，取分数低的。实测 UTF-8 得 -44、GB18030 得 -50，判为 GBK 正确。

### 6.2 参数双重编码导致接口返回空

**现象**：财务接口返回 200 但数据为空，与 6.1 表现相同、原因完全不同。

**排查**：对比 `requests` 直接请求与封装层请求的实际 URL：

```
正常：filter=%28SECUCODE%3D%22300750.SZ%22%29
异常：filter=%2528SECUCODE%253D%2522300750.SZ%2522%2529
```

**根因**：代码里先 `urllib.parse.quote()` 预编码，`requests` 的 params 又编码一次，
`%` 变成 `%25`。上游不认识这个过滤器，返回空结果而非报错。

**解法**：传原始字符串，交给 requests 编码。

**教训**：这类静默失败比报错更危险——`ok: true` 但数据为空，只有靠对账才能发现。

### 6.3 更换数据源绕开封锁

**现象**：`clist` 被 WAF 封禁后，同业对比、板块行情、全市场列表全部失效。

**排查**：逐个探测东财各子域，发现 `datacenter-web.eastmoney.com` 完全正常。

**解法**：
- 行业归属改用 `RPT_F10_CORETHEME_BOARDTYPE`，其中有 `BOARD_TYPE='行业'` 字段
- 行业成分与基本面改用 `RPT_BOARD_CONSTITUENT`，自带净利润、PE 历史分位、股息率
- 板块涨跌改用 `RPT_INDUSTRY_FUNDFLOW`

**顺带解决的问题**：新数据源比原方案信息更丰富。原 `clist` 只给动态 PE，
新接口给 `PE_TTM_PERCENTILE`（历史分位），对估值判断更有价值。

### 6.4 行业层级选择

一只股票同时属于「电力设备 → 电池 → 锂电池」三级行业。
取一级行业做同业对比，会把宁德时代和特变电工、正泰电器放在一起，没有可比性。

**解法**：按 `BOARD_RANK` 取最大值（最细分），并排除名字带 Ⅱ/Ⅲ 的重复层级。
实测对比结果从「电力设备行业第 1 名（对手：特变电工、正泰电器）」
变为「锂电池行业第 1 名（对手：亿纬锂能、科达利、欣旺达）」。

### 6.5 语义正确性：历史解禁不是风险

初版把解禁记录全部当作风险命中，导致两年前已完成的解禁也报警。

**解法**：只取今天到未来 90 天的记录；无记录时写「未来 90 天内无解禁」而非静默。

### 6.6 多副本导致改动不生效

**现象**：修好 `peers()` 后重新运行，`pe_vs_peer_median_pct` 仍是 `None`。

**根因**：`fin` 命令是 `pip install -e` 安装的，指向的是 profile 内的副本
（`~/.hermes/profiles/finance/src/fin`），而编辑的是仓库里的 `src/fin`。
两份代码从此分叉，改仓库不生效。

**解法**：明确"仓库是唯一可编辑源头"，加 `scripts/sync_payloads.py`
把 `src/` 与 `skills/` 同步到 profile 和分发包，并在同步时统一换行符为 LF
（否则 Windows 下 CRLF/LF 差异会导致每次都被判定为"有变更"）。

这类问题在"同一份代码要分发到多个运行位置"的项目里很常见，
不解决的话调试时会反复怀疑代码逻辑。

### 6.7 其他已修复问题

| 问题 | 根因 | 修复 |
|---|---|---|
| 指数名称为 `0.0` | `ulist.np` 的 `f58` 字段返回 0 | 用 `f12` 反查本地指数表 |
| 涨跌家数全是 0 | `stock/get` 的 `f104/f105` 恒为 0 | 改用 `ulist.np` 且带 `f12` |
| 快讯返回空 | 缺少 `req_trace` 参数 | 补毫秒时间戳 |
| 板块去重后只剩 1 个 | 无涨跌家数时所有 key 都是 `(None, None)` | 增加 `has_counts` 判断 |
| 成分表报「列不存在」 | 该表没有 `SECURITY_NAME_ABBR` | 简称改从腾讯行情补 |
| 同业数据循环引用 | `primary["levels"] = industries` 且 primary 在列表内 | 浅拷贝后再挂 |

## 7. 评测

### 7.1 数字保真度检查

`evals/check_fidelity.py`：把 CLI 输出的 JSON 展平成数值集合，
抽取报告中的所有数字，逐项比对，输出保真度与可疑数字列表。

实测结果：

| 报告 | 保真度 | 可疑数字 |
|---|---|---|
| 全部数字来自 CLI | 100%（11/11） | 无 |
| 混入一个编造数字 37.5 | 92%（11/12） | `[37.5]` |

设计细节：排除股票代码与日期片段（`2026-10-22` 曾被拆成 `-10`、`-22`），
否则误报率过高。正则用负向后视 `(?<![\d\-])` 避免匹配日期中的负号片段。

### 7.2 黄金问题集

`evals/golden.jsonl` 共 10 条，每条声明期望命令与检查点，例如：

```json
{"question": "帮我看看宁德时代", "skill": "fin-research",
 "expect_cmds": ["stock.quote", "stock.financials"],
 "checks": ["PE 用 pe_ttm", "财务标明报告期", "有风险段"]}
```

覆盖：行情解读、个股研究、同业对比、歧义消解、休市处理、风险扫描。

**当前状态**：问题集与检查脚本已完成；端到端跑批尚未执行（单次运行需调用模型，
成本较高）。这是已知的未完成项，见第 9 节。

## 8. 交付形态

以 Hermes Profile Distribution 分发：

```
distribution/
├── distribution.yaml    清单：版本、依赖、哪些文件随更新覆盖
├── SOUL.md              角色设定
├── config.yaml          模型留空，由使用者填写
├── .no-bundled-skills   阻止灌入 Hermes 的 87 个内置技能
├── skills/              fin-market / fin-research
├── src/                 CLI 代码
└── cron/jobs.json       预置定时任务
```

客户侧一条命令安装：

```bash
hermes profile install <包地址> --name finance --alias
```

**分发语义**（Hermes 原生支持，非自行实现）：
- 分发自有文件（`SOUL.md`、`skills/`、`cron/`、`src/`）随 `profile update` 覆盖
- 用户自有数据（`memories/`、`sessions/`、`auth.json`、`.env`）永不触碰
- `config.yaml` 在更新时默认保留，避免覆盖客户的模型配置

安全约束：**分发包不含任何 API Key**。`auth.json`、`.env`、`custom_providers`
都在排除列表内，客户必须自行配置模型。

## 9. 已知限制

诚实列出，不粉饰：

| 限制 | 影响 | 现状 |
|---|---|---|
| 涨跌家数依赖单一接口 | 该接口被封时缺失 | 返回 `unavailable`，用涨跌停统计替代 |
| 本地符号表未建 | 无 | 名称解析已改走搜索建议接口，更轻且不依赖 push2 |
| 全市场涨跌分布未实现 | 无 | 需逐只行情，5563 只按腾讯 66 只/请求约 85 次请求，实测 224 秒，性价比低 |
| 北向资金未实现 | 无 | 2024-08 起停止实时披露，只有月度持股 |
| 黄金问题集未跑批 | 评估不完整 | 脚本与用例已就绪 |
| 个股资金流已接入未使用 | 无 | `fflow` 依赖 push2，不稳定 |
| 定时任务需 gateway 常驻 | 不启动则不会自动运行 | 已写入部署文档 |
| 桌面端依赖外部 hermes-agent | 只装桌面端无法运行 | 桌面端 Electron 壳不含 Python 运行时，需另装后端 |

## 10. 代码结构

```
src/fin/                     2,448 行
├── cli.py            306    命令入口，只做参数解析与输出
├── config.py          62    常量、TTL、指数定义
├── envelope.py        45    统一 JSON 契约
├── http.py           182    限速、重试、编码识别、缓存降级
├── store.py          159    SQLite 缓存与符号表
├── symbols.py        132    代码换算、名称解析
├── sources/
│   ├── eastmoney.py  447    20 个接口薄封装，不做语义加工
│   └── tencent.py     85    行情主路径
└── api/
    ├── market.py     361    指数、涨跌家数、情绪、板块
    ├── stock.py      243    行情估值、财务、行业识别、同业
    ├── news.py       152    快讯、新闻、公告、研报、日程
    ├── risk.py       163    风险规则引擎

scripts/
└── sync_payloads.py        把 src/ 与 skills/ 同步到 profile 与分发包
```

分层严格单向：`cli → api → sources → http`。
`sources` 只返回上游原始 JSON，所有语义加工（字段映射、warnings、口径判断）都在 `api`。
数据源替换只改 `sources`，不影响上层。

## 11. 验证证据（2026-10-22 收盘后实测）
