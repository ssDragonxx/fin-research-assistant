## 一、数据源可用性实测（2026-10-22）

开发当天东方财富 `push2.eastmoney.com` 对本机 IP 触发了 WAF 封禁，导致反复失败。
这直接改变了架构选型。

| `push2/qt/stock/get` | 间歇 | 单独请求时通常可用，高频后断连 |
| `push2/qt/ulist.np/get` | 间歇 | 涨跌家数、多指数行情 |

## 二、架构上的关键决策

### 1. 腾讯作为行情主路径，东财补充

最初设计是东财为主、腾讯兜底。实测后反转：

- 腾讯单只/小批量行情从不失败，字段齐（PE-TTM、PB、市值、换手、量比）
- 东财 `push2` 是唯一会被封的环节

所以 `api/stock.py::quote()` 先取腾讯，再尝试东财补 ROE、行业、营收同比，
东财失败只产生一条 warning，不影响主结果。两个源的 PE 差异 >15% 时主动告警。

### 2. 同业对比不依赖 `clist`

`clist` 取板块成分是最自然的做法，但它恰好在封禁范围内。
改用 `RPT_BOARD_CONSTITUENT`（datacenter-web）：

- 按 `BOARD_CODE`（纯数字，不是 `BK1033`）查成分
- 自带 `ACCUM_NETPROFIT`、`PE_TTM_PERCENTILE`、`DIVIDEND_RATIO`
- 不含股票简称 → 用腾讯批量补
- 不含价格/PE/PB → 用腾讯批量补

筛选逻辑按净利润规模找最近的同业（而非随机取前几家），
并排除 ST。这比按市值排行更接近"可比公司"的投研惯例。

### 3. 行业层级的选择

`RPT_F10_CORETHEME_BOARDTYPE` 返回一只股票的多个行业板块，
宁德时代同时属于「电力设备 → 电池 → 锂电池」。

按 `BOARD_RANK` 取最大值 = 最细分行业。因为一级行业「电力设备」
有 300+ 成分股，同业对比没有意义；「锂电池」才是真正可比的口径。

### 4. 涨跌家数的口径

`stock/get` 的 `f104/f105` 恒为 0（实测），只有 `ulist.np` 带 `f12` 才有值。

`ulist.np` 不可用时返回 `unavailable: true` 而不是 0——**缺数据必须是缺失，
不能是零**。同时用涨停/跌停统计作为替代情绪指标，并在 warning 里说明替换。

沪指 + 深成指 = 全市场（创业板/科创50 是子集，不能相加）。

## 三、踩过的坑（按发现顺序）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | `pz=6000` 只回 100 条 | 服务端硬限制 | 翻页聚合 |
| 2 | 财务数据中文乱码且静默返回空 | 接口声明 `charset=UTF-8`，实际 GBK，且 UTF-8 能"成功"解码 | `_decode` 用乱码字符评分（拉丁扩展/希腊/西里尔 vs CJK）判断 |
| 3 | 财务接口返回 0 行 | `filter` 手动 `quote()` 后被 requests 二次编码成 `%2528` | 传原始字符串 |
| 4 | 涨跌家数全是 0 | 用错接口 | 改 `ulist.np` + `f12` |
| 5 | 指数名称是 `0.0` | `f58` 在 `ulist.np` 返回 0 | 用 `f12` 反查 |
| 6 | 板块排名出现「电机Ⅱ」「电机Ⅲ」 | 496 个板块含多层级 | 按涨跌家数去重；无家数时只按名称过滤（不能合并） |
| 7 | 板块去重后只剩 1 个 | 无涨跌家数时所有 key 都是 `(None, None)` | 增加 `has_counts` 判断 |
| 8 | 快讯返回空 | 缺 `req_trace` | 补毫秒时间戳 |
| 9 | 公告命令崩溃 | `news` 子命令的位置参数叫 `keyword` 不叫 `target` | `_target()` 兼容两个字段 |
| 10 | 成分股接口报"列不存在" | 该表没有 `SECURITY_NAME_ABBR` | 简称从腾讯补 |
| 11 | 两年前解禁被当成风险 | 没过滤日期 | 只取今天→90 天后 |
| 12 | 同业数据循环引用 | `primary["levels"] = industries` 且 primary 在 industries 里 | `dict()` 浅拷贝 |
| 13 | 全市场扫描太慢 | 腾讯 66 只/请求，5563 只 = 85 请求，实测 224 秒 | 放弃扫描，改用 `RPT_BOARD_CONSTITUENT` |
